# 输入框消息队列与插队

## 目标

生成进行中，输入框写好的消息按发送键进入当前会话的队列，本轮结束后按顺序自动发出；队列中的任一条可以“插队”，让当前轮在下一次工具调用结束时让出，随后立即发出这条消息，模型带着已完成的工具结果处理新指令。

## 已确认的产品决定（2026-10-23 用户确认）

- 发送键在生成中为“排队”；插队是对已排队消息的操作。没有工具边界的纯文字回复，插队消息在本轮结束后第一个发出。
- 本轮失败或被停止时队列暂停，保留内容，由用户继续或逐条处理。
- 队列按会话持久化，应用重启后以暂停状态恢复，不自动发出。
- 排队消息支持图片与文档附件，入队时从草稿取走；图片在入队时复制进应用私有目录，避免重启后失去 URI 读取权限。

## 非目标

- 不做跨会话的全局队列；一次只有一个会话在生成，轮到发送时另一会话在生成则暂停（BUSY）。
- 不在会话未打开时后台接续发送：本轮结束时没有停留在该会话，队列暂停（INTERRUPTED）。
- 不改变审批语义：等待审批时插队等同立即发送，沿用新一轮发送关闭待审批的现有行为。

## 方案

插队不在运行中的轮次里插入用户消息，而是让当前轮在工具轮边界“让出”结束，再以插队消息正常开启新一轮。历史形态为“用户 → 助手（工具调用）→ 工具结果 → 用户（插队）→ 助手”，各协议都接受；轮次结构、记忆后处理、重新生成与统计都保持“一条用户消息一轮”。

- 后端（Codex CLI，gpt-6.1-sol xhigh，独立 worktree `../Nexara-wt-queue` 分支 `feat/composer-queue`）：持久化队列存储、生成循环让出、运行时接线、ChatViewModel 队列状态机、会话删除清理与对应测试。任务书见 `.agent/tmp-agent-reports/composer-queue/brief.md`。
- 界面（主控）：契约 `ui/chat/ComposerQueueUiState.kt`；浮岛队列托盘（排队条目、插队、编辑、删除、移到最前、暂停原因与继续）；生成中有输入时发送键为排队并保留停止；文案、截图测试、设备测试；ChatRoute 接线。
- 文件所有权：后端不改 `ui/chat/ChatScreen.kt`、`ui/chat/ChatRoute.kt`、`ComposerQueueUiState.kt`、`ComposerIsland.kt`、`GenerationActivityRow.kt` 与资源文件；主控在合并前不改后端所列文件。

## 验收

- JVM：队列存储持久化与恢复、图片复制与清理、生成循环在工具边界让出与纯文字不让出、ViewModel 入队/自动发出/暂停/插队/编辑/删除/移到最前/BUSY/INTERRUPTED、各协议对“工具结果后紧跟用户消息且无最终回答”的历史序列化。
- 门禁全套、Play 构建与渠道清单检查。
- 设备测试：生成中排队、插队托盘交互。
- 真机（DeepSeek V4 Flash）：排队自动发出；工具链中插队后模型基于已有工具结果回应；停止后暂停与继续；杀进程重启后队列以暂停恢复。
