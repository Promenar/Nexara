# 模型选择器目录解析与设置页排版（2026-10-16）

## 目标

1. 修复会话等模型选择器漏掉大量已启用模型的问题。
2. 整理提供商模型管理、提供商列表、工具设置（预设 / 技能包 / MCP）页面的排版，并排查同类问题。

## 根因

- OpenAI 兼容同步为每个模型保存一份通常为空的供应商元数据；选择器投影 `toModelSelectionUiModel` 由调用方传入 `ModelMetadataResolver()`，它只含内置覆盖表，不含运行时加载的完整模型目录。目录内的对话模型因此被判为工作负载未知，被会话过滤 `isChatSelectionCandidate` 隐藏，名称也退回原始 ID。受影响：会话设置、默认模型、检索高级设置、智能体编辑、智能体中心五个选择器。
- 模型管理页把搜索、操作按钮、目录信息作为固定头部，列表在其下方硬裁切；设置页骨架的底部系统栏留白被当作外层 padding，列表在导航栏上方再被硬裁切。
- 工具设置页把整个标签页内容放进一个无内边距的圆角卡片：技能包说明首字被圆角裁掉、按钮贴边；预设工具行右侧的齿轮与开关挤占正文宽度，说明折成多行；循环限制步进器挤压说明。
- 提供商列表把类型、启用状态、密钥状态塞在一行小字里，常态信息与需要处理的信息混在一起。

## 方案与验收

| # | 修复 | 验收 |
|---|------|------|
| M | 投影默认使用 `ModelCatalogRuntime.resolver`，五个选择器统一改用运行时目录 | 单测：空供应商元数据 + 目录记录 → 进入会话可选列表并显示目录名称；修复前失败 |
| L1 | 模型管理页：搜索栏固定，其余（操作、目录信息、提示、模型）同一列表滚动；目录信息压缩为一行；列表顶部滚动时渐隐，底部延伸到导航栏后 | 截图基线 |
| L2 | 提供商列表：首字母头像 + 名称 + 状态；副行只列类型与主机；密钥缺失才以警示色单独显示 | 截图基线 |
| L3 | 工具设置：循环限制改为标题与步进器同行、说明独占整行；预设工具行只保留开关，可配置项在说明下方给出“配置”入口，分隔线内缩且末行不画；技能包说明放到卡片外，空态与按钮有内边距；MCP 卡片同样整理 | 截图预览 + 设备目测 |
